# Implementation Status — FAULTLINE XR

## Current playable implementation

The competition submission is now the **WebXR implementation in `web/`**, not the earlier Unity/C# reference scaffold.

It is a production static build generated by TypeScript, Vite, and Three.js. It runs in Meta Quest Browser with WebXR hand tracking and also provides a desktop preview mode for flow review.

## Build state

Verified in this environment:

- `npm install` — completed.
- `npx tsc --noEmit` — passes.
- `npm test -- --run` — passes; **12 domain tests passed**.
- `npm run build` — passes; output generated at `web/dist/`.

The current build contains one JavaScript chunk of approximately **610 KB minified / 157 KB gzip**; Vite reports a chunk-size warning but completes successfully.

A physical Meta Quest headset was not available for device verification in this environment. The implementation reads WebXR hand joints and requests an immersive-vr session, but device-specific behavior still needs a final check in Quest Browser before submission.

## Legacy Unity/C# reference

The files under `Assets/Faultline/`, `Tests/`, and the older Unity-oriented documents are retained as reference material.

The repository does **not** contain:

- `ProjectSettings/` or generated Unity project files.
- Unity scenes or prefabs.
- A compiled APK.
- A Meta XR SDK package.
- Evidence of a Unity compile, headset run, or device test.

Therefore, the C# reference code is **not claimed to compile**, and the Unity path is not the submission path.
